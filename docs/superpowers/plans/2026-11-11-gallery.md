# Gallery & Videos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hardcoded 3-image strip on `/news` with an admin-managed, aspect-true, continuous `/gallery` feed of outings (swipeable strips) and singles (justified rows), photos + short videos + YouTube.

**Architecture:** Two Supabase tables (`gallery_entries`, `gallery_items`) and two buckets (private `gallery-originals`, public `gallery`). Admin uploads go browser → Storage via signed upload URLs; a server action then runs `sharp` to fix orientation, record true dimensions and write WebP variants into the public bucket. The public page server-renders the first page of entries and loads more via a public server action; pure layout/feed/YouTube logic lives in small tested modules under `src/lib/gallery/`.

**Tech Stack:** Next.js 16.2.7 App Router (server components, server actions), Supabase (service-role client + Storage signed uploads), `sharp` (already a dependency), Tailwind 4, `tsx --test` (node:test) for unit tests.

**Spec:** `docs/superpowers/specs/2026-11-11-gallery-design.md` — read it first. Every task implicitly includes it.

## Global Constraints

- Next.js 16 has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` (server actions, `revalidatePath`, metadata, images) before writing code in a task that touches them.
- Never crop, stretch or squash media. Tiles size from stored `width`/`height`; images render with `object-contain` only inside boxes whose ratio already matches (or a clamped box with branded backdrop).
- Layout ratio clamp: **0.5 – 2.5**. When clamped, show the whole image contained on the backdrop `#0b2a3d`.
- YouTube: ratio 16:9; Shorts (`/shorts/`) 9:16. Player only loads on open, from `https://www.youtube-nocookie.com/embed/<id>`.
- Image variants: WebP at widths **640 / 1280 / 2048**, never upscaled; blur placeholder; `sharp().rotate()` before reading dimensions.
- Upload cap **50 MB** per file (both buckets). Uploader copy for video: "Clips up to about 30–40 seconds (50 MB). For longer videos, upload to YouTube and paste the link."
- Image originals → private `gallery-originals`. Public `gallery` bucket holds only WebP variants and video files. Video uploader shows: "Video files can contain the location they were recorded at."
- Uploads never pass through a server action/route body (11 MB `bodySizeLimit`).
- Every admin page and server action calls `requireAdmin()` itself; never accept a user/session parameter.
- Feed videos: `preload="none"`, never autoplay with sound.
- Order: `taken_on desc, published_at desc, id desc`.
- Published entries edit live; new items on a published entry go public once `processing='ready'`. `hidden` pulls a single item.
- Public queries return only `status='published'` entries, items with `processing='ready' and hidden=false`, and drop entries left with zero items.
- Nav label "Gallery", placed directly after "News & Media" in `src/lib/site.ts`.
- Empty state copy: "Photos from the campaign trail are coming soon."
- Use brand tokens from `src/app/globals.css`; no `alert`/`confirm`.

## Review Focus

1. **Phone photo with EXIF orientation 6 (portrait shot stored landscape)** → stored width/height must be the *displayed* portrait dims. Test in Task 4.
2. **Last row / lone panorama in a singles block** → row must not inflate to giant height; panorama is clamped to 2.5, shown whole. Test in Task 2 + visual check in Task 7.
3. **YouTube URLs with extra params or odd hosts** (`&t=30s`, `?si=…`, `m.youtube.com`, `youtu.be/ID?si=`, `/live/`) parse; playlists, channels and non-YouTube URLs are rejected with a message. Test in Task 1.
4. **Published outing whose items are all still processing or failed** → not rendered at all (no empty strip). Test in Task 2 (`toPublicEntries`) and Task 3 query.
5. **Several entries sharing the same `taken_on` across a page boundary** → no duplicates, no gaps. Test in Task 2 (cursor filter) + scratch check in Task 3.

- Produces — each action: `await requireAdmin()` first, then calls the matching op, then `revalidatePath("/gallery")` and `revalidatePath("/news")` for anything that can change public output. Action signatures:
  - `createEntry(kind: EntryKind): Promise<string>` → draft with title `""`, slug `draft-<random>`; returns id.
  - `updateEntry(id: string, fields: { title: string; body: string | null; place: string | null; takenOn: string }): Promise<void>` — reslug from title (unique, suffix on clash, like `saveDraft`); for singles with empty title, slug `moment-<id first 8>`.
  - `setEntryStatus(id: string, status: "draft" | "published"): Promise<{ error?: string }>` — publishing requires ≥1 ready item (else `{ error: "Add at least one photo or video first." }`) and an outing title (else `"Give the outing a title."`); sets `published_at` the first time.
  - `deleteEntry(id: string): Promise<void>` — removes all storage objects for its items, then the row (cascade).
  - `createUpload(entryId: string, file: { kind: "image" | "video"; contentType: string; size: number; width?: number; height?: number; durationS?: number }): Promise<{ itemId: string; upload: { signedUrl: string; token: string; path: string; bucket: string }; poster?: { signedUrl: string; token: string; path: string; bucket: string } } | { error: string }>` — rejects size > 52428800 or disallowed type with a plain message; rejects a second item on a `single`; inserts item `processing='pending'` at the end position; images → `gallery-originals/images/<itemId>.<ext>`; videos → `gallery/videos/<itemId>.<ext>` + poster target `gallery-originals/posters/<itemId>.jpg`; video dims must be integers 1–8192 and duration 0–600, else error.
  - `finalizeItem(itemId: string): Promise<{ error?: string }>` — download the original (image) or poster (video), `processImage`, upload variants to `gallery/items/<itemId>/<w>.webp` (upsert), store `variants`, `blur`, and for images `width`/`height`; set `ready`. On `UnsupportedImageError` set `failed`, `error = "Unsupported photo format — export as JPEG and try again."`; other failures set `failed` with a generic message. Also set the entry's `cover_item_id` if null.
  - `addYouTube(entryId: string, url: string): Promise<{ error?: string }>` — `parseYouTubeUrl` or `{ error: "That doesn't look like a YouTube video link." }`; insert ready item, `width/height` 1600×900 (Shorts 900×1600).

- Ops in `ops.ts` mirror these names with an `Op` suffix and the same parameters (no auth, no revalidate) so the scratch script can call them.
